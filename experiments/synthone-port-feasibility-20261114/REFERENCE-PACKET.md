# Genuine AudioKit Synth One engine: first executable feasibility packet

## Result

The genuine Synth One per-note DSP and its two-LFO/combined-route computation now compile for host and pi32v2. The isolated host probe consumed all 906 supplied presets, rendered 3,600,384 source voice calls, and reported no nonfinite samples. This is not a complete engine port, firmware fit, app-audio match, or device CPU result.

The unmodified upstream allocation strategy is not a small-engine drop-in: its Soundpipe initialization requests 8,044,288 bytes on this 64-bit host before Objective-C objects, C++ containers, parameter wrappers or allocator overhead. Four ten-second float delay lines account for 7,056,208 bytes. This makes table/FX ownership and memory placement the first architecture decision, not source access or C compiler availability.

## Source architecture and semantic contract

All Synth One paths below are relative to `AudioKitSynthOne/` at the full pin above.

- `DSP/Audio Unit/S1AudioUnit.h:14`: six-voice limit. `DSP/Note State/S1NoteState.mm:33–86,174–224,337–403`: two independent morphing table oscillators, sub sine/square at one/two octaves down, sine FM, noise, separate amp/filter ADSRs, and a selectable Moog ladder / Butterworth BP / HP filter. All three filters are computed even when only one is selected.
- `DSP/Kernel/S1DSPKernel.hpp:27–29`: 4,096-sample tables, four shapes, thirteen bandlimit rows. `DSP/BandlimitedWavetables/bandlimitedWaveforms.json` gives triangle, square, fixed PWM, saw order. Source oscillator index 0..1 is a morph across all four shapes, not DnBOX's saw/pulse blend. The supplied wavetable data is public source data; no user-bank payload is needed to reconstruct it.
- `DSP/Kernel/S1DSPKernel+process.mm:72–121`: two independent smoothed LFOs, each sine/square/saw/reverse-saw, and a third routing choice that is their average, not a third independent LFO. Routing IDs 0..3 are selectors, not normalized depths. Targets include cutoff, resonance, oscillator mix, reverb mix, amp decay, noise, FM, detune, filter depth, pitch, crush and tremolo.
- `DSP/Kernel/S1DSPKernel+process.mm:145–312`: sample-rate reduction, tremolo, auto-pan, phaser, low-pass into four-line ping-pong delay, reverb input HPF/compression, RevSC, wet compressor, master compressor and 50 ms stereo widening. There is no Juno chorus in this source path.
- `DSP/Kernel/S1DSPKernel.hpp:269–279,355–405`: authoritative min/default/max table. Relevant values: cutoff 64/20000/22050 Hz; resonance 0/.1/.98; filter-envelope depth 0/0/1.2; amp A .0005/.05/2 s, D .005/.005/2 s, S 0/.8/1, R .004/.05/2 s; filter A .0005/.05/2 s, D .005/.05/2 s, S 0/1/1, R 0/.5/2 s; oscillator detune -4/0/4 with note-relative scaling, sub octave toggle 0/0/1, sub shape toggle 0/0/1; master level 0/.5/2. LFO rate expressions evaluate to 1/1920..80 Hz; the nearby source comment's 53.3333 upper number is stale.
- `Presets/Preset.swift:204–286,318–330` and `Presets/PresetDataManager.swift:77–144,165–224`: JSON stores physical DSP values, not knob positions. Missing recognized values use DSP defaults, which differ from several Swift property initializers. `cutoff` is Hz, ADSR times are seconds, waveform1/2 are 0..1 morph coordinates. A bank is a top-level array (`Presets+UIDocumentPickerDelegate.swift:20–28`), unlike J6's observed object/parameterValues shape. No automatic JSON-shape product authentication is justified.
- `Generators/GeneratorsPanelController.swift:98–106`: cutoff/master knob taper 2 is UI behavior. `S1DSPKernel+getSetSynthParameters.mm:21–28` clamps physical values; dependent rate/time setters additionally tempo-quantize or apply the 0.4 normalized-control taper. Do not apply the UI taper to already-physical saved cutoff/times.
- `S1NoteState.mm:238–261,305–332`: filter law is `clamp(C*(1-m+m*Ef),64,22050)`, not DnBOX's `base + 7000*EnvAmt*Ea`. Separate filter contour is meaningful. Source Soundpipe `adsr.c:36–94` uses exponential coefficients and a .99 attack threshold; DnBOX Juno's linear A/D and exponential R are not interchangeable by matching time labels.

## Executed evidence

- `probe/host-allocation.log`: requested Soundpipe bytes at 44.1 kHz, float32: context 244; 53 tables 870,684; four ten-second delays 7,056,208; RevSC 99,200; widen 8,860; seven mono/poly note-state DSP allocations 3,304; remaining global processors/compressors 5,788. Total 8,044,288, 383 malloc requests. This is requested data, not platform allocator footprint. `-fno-builtin` prevents malloc+memset becoming uncounted calloc.
- Immutable sample payload alone is `53*4097*4 = 868,564` bytes. Four delay payloads alone are `4*(441000+1)*4 = 7,056,016` bytes. Allocation remains active even when FX mix is zero because upstream init is unconditional. The source allows delayTime up to 2.5 s and uses two lines at twice that value, so blindly reducing every line below 5 s breaks valid settings.
- `probe/target-compile.log`: 19 real AudioKit C modules compile with clang 4.0.1, `-target pi32v2 -mcpu=r3 -mfprev1 -Os -ffp-contract=off -fno-fast-math`. Their aggregate object `.text` is 11,894 B before section GC, libm/compiler helpers, Synth One kernel, tables and integration. This is not linked firmware size.
- `probe/voice-target-compile.log`: adapted real per-note and LFO source compiles for pi32v2, object `.text` 2,840 B. Only the Apple-facing interface/imports and missing M_PI definition are adapted; source per-note arithmetic is preserved. This is object compilation, not full target link/run.
- `probe/voice-probe.log`: all 906 source-recognized supplied records exercised for 1,024 frames each at 44.1 kHz, with release at 3/4 of the probe. 384 mono programs use one voice; remaining programs use six. 3,600,384 source voice calls, 906 nonzero programs, no NaN/Inf. Peak before global FX is 8.54674053. Default/selected master compression and gain are therefore not safely discarded as inaudible details.
- Recorded host render time was 1.025 s / 927,744 mixed mono/poly frames on this run, 1,105 ns/frame. This is a noisy host observation, not AC79 CPU, a speed guarantee, or an integrated DnBOX comparison. Source bank controls are clamped and loaded statically; no parameter ramp, source tempo-rate re-snapping, preset-dependent tuning, source event allocation, arp, sequencer, global FX or app audio comparison is implemented here.
- `probe/target-undefined-symbols.txt`: actual target objects still require double-precision helpers and libm functions, including `__muldf3`, `__divdf3`, `exp`, `tanh`, `pow`, `sin`, `cos`, `log`, and `sqrt`. DnBOX `fastmath.h:1–24` explicitly describes float-only FPU/no-libm. Object compilation does not resolve this link/CPU problem.

## Recommended next implementation cut for the incumbent owner

Keep the standalone Synth One voice source as the behavioral oracle. Create a separately versioned Synth One state/engine identity; never reinterpret Juno ID3 or its old 18 macros, DNPR or saved pattern cells as 114-field Synth One state. Leave existing Juno intact. Keep this corpus and all derived parameter/audio files private.

First port the real dual-morph/sub/FM/noise + separate amp/filter envelopes + selectable filter + two-LFO routing topology with static, caller-owned memory. Bind immutable public waveform arrays directly from suitable read-only storage instead of allocating/copying them to RAM. Preserve interpolation and band selection. Quantized/compressed/regenerated tables need explicit A/B error evidence before acceptance, not an assumed equivalence.

Reuse DnBOX infrastructure and proven optimization patterns where semantics survive: fixed memory pools, event-bounded block scheduling, current finite-domain math primitives with measured error, and exact inactive-path work elimination. Do not substitute a Juno envelope or filter simply because it is cheaper. Gate any fastmath rewrite by matched impulse, held-note, release, resonance and modulation renders against this source oracle, then target link/memory and whole-instrument cycle tests.

For FX, either retain enough source-specific storage/processing for imported programs, or expose an explicitly approximate shared-DnBOX-FX mode and report unsupported/mismatched behavior. Existing `fxbus.h:2–25` is a 12-bit/comb+allpass/send design, not RevSC plus source insert compression/phaser/four-line delay; it saves resources but changes presets. Shared project FX also cannot silently become per-preset insert state across two simultaneous instruments.

Miami's optimizations are useful design evidence, not drop-in Synth One proof. At exact PR925, `miami_interpolation.h:7–39` is guarded for positive-normal base plus smaller negative difference; Synth One's signed four-table oscillator interpolation violates that domain. Current Miami idle/event-free code preserves precise clock and notification state; Synth One's LFO ports, release envelopes, always-computed filters and evolving delay/reverb tails must continue when their original algorithm would. The settled-FX bypass requires its own proof here. Do not cite closed/unmerged PR814 as an adopted Miami coefficient cache. The parallel Chicago audit also found the older cache candidate #813 absent from accepted d158 and the supposed successor #864; cache design ideas need fresh source and behavior proof, not an adoption claim.
