# SMK-37 MIDI capability matrix

Inspected firmware: `gobbajogger/X0X37-for-Loopy-Pro` at `94197fc839b00aff47b98ca02f3c6396e4a6eabf`. This is source evidence for this pin, not physical Elite/Pro qualification. Paths and lines below refer to that exact source. The source snapshot is `source/gobbajogger-X0X37-for-Loopy-Pro-94197fc/`.

First source consumption: `firmware/src/app/engine.c:1635`, the actual `midi_in()` dispatcher. USB ingress is `firmware/src/usb.c:1039–1067`; source tags are `firmware/src/app/plat.h:101–102`: 0 USB, 1 peripheral Bluetooth, 2 TRS. A message reaching a wire parser does not mean the instrument implements its musical meaning.

## Routing that changes the meaning of a message

- Human MIDI channel defaults are 909=10, 808=11, Synth1=2, Synth2=3, BREAK=4. They are project settings, not fixed protocol channels: `firmware/src/seq/sequencer.c:29–34`, `firmware/src/app/project.c:809–820`. Project channel value 0 selects the default, 1–16 selects that channel, >16 turns the part's MIDI channel off. Selecting a channel in this harness changes only outgoing message channels; it cannot discover or change the firmware's assignment.
- BREAK owns its matching note channel before kits and synths, including channel collisions (`engine.c:1720–1723`). Kits own their matching note channels before synths (`engine.c:1725–1742`). Multiple synths sharing a channel can both respond (`engine.c:1744–1796`). Muted/off parts suppress positive Note On according to `SEQ_PART_OFF`; source releases retain their separate paths.
- SMK APC clip mode or a completed APC host handshake on that link can consume notes <=98 and certain CCs before the sound engine (`firmware/src/app/main_fm1.c:320–346`; USB call `firmware/src/usb.c:1059–1067`). The engine has additional clip-mode note filtering (`engine.c:1686–1702`). A generic browser cannot infer performance context from a MIDI port name.
- USB/peripheral BLE SMC User mode reserves channel 16 for selected notes and CC16–23/40–47 (`firmware/src/app/smc_protocol.h:29–41`; `smc_mixer.c:390–418`). Central BLE controller input has a separate callback and is not the browser's generic performance route (`engine.c:1676–1684`). The isolated harness excludes channel16 entirely as a conservative choice; the firmware does not reject every channel16 musical message.

## What the browser can observe

With notes output enabled, the sequencer emits synth NoteOn/Off and drum GM pairs; synth output flushes preserve original output channel and note identity (`firmware/src/seq/sequencer.c:152–202,333,372`). With clock output enabled and internal operation, it emits24ppqn F8 (`sequencer.c:1139–1141`); generated Start/Continue/Stop have source/echo conditions (`sequencer.c:760–801`). `firmware/src/app/engine.c:1186–1190` serializes through `plat_midi_out`, whose USB/BLE output is suppressed in clip mode (`firmware/src/app/plat_fm1.c:275–286`). This observed stream has no correlation IDs and is not an authoritative snapshot, current knob-state feed, lease, or command acknowledgement.

The isolated harness must receive into a display/log only. It must never call its transmit path in response. A received NoteOff can remove a received highlight, but must not cancel a locally held release obligation. Clear received highlights on disarm, channel change and disconnect to avoid stale presentation. Loss/reconnect cannot prove previously sent NoteOff, CC64=0, pitch-center or Stop reached a device; do not replay a prior session onto a new endpoint.

## Missing real-time remote protocol

The removed Felucca editor is expressly historical (`web/EDITOR_PROTOCOL.md:1–5`). Active `firmware/src/app/editor.c:4–8` says parameter/preset/track commands are not answered; `ED_INFO` advertises zero engines/parameters (`editor.c:874–881`), and unknown commands return without a reply (`editor.c:1079–1080`). Remaining PROJECT/sample/maintenance commands are not a replacement parameter API. The harness excludes all SysEx, project transfer and device maintenance.

A complete remote UI would need a versioned capability/model/context handshake, defined engine/part/parameter identities, validated get/set and feedback, command errors/ACKs and resynchronization semantics. Transactional editor/sync changes remain with the existing #52/#104 protocol owner. `web/offline-sequencer/SYNC.md:62–77` explicitly requires owner-bound snapshot and revision-checked atomic commit and rejects current read/write before transmission. The existing `fde38845e7474fffae24ae835907d7ca9197b589` proposal provides those model tests; this stage must reuse their findings rather than integrate or reimplement that firmware ownership.

## Existing browser surfaces checked

No equivalent live performance browser controller was found in the pinned `web/` tree. `web/offline-sequencer/README.md:41` explicitly excludes live triggering/playback/MIDI requests; lines17–20 keep DeviceSync disabled and name the separate TouchOSC companion. Existing browser MIDI request/listener paths belong to installer, project transfer, sample transfer and shared transport helpers (`web/x0x_installer.html`, `web/x0x_projects.html`, `web/x0x_breaks.html`, `web/fm1ota.js`). Those have different contracts and must not be repurposed as authorization to install, transfer or send SysEx. This is a scoped source finding, not proof no implementation exists in every other unobserved work thread or branch.
