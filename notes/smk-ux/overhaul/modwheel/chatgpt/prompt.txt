DnBOX SMK-37 firmware (JieLi AC79, 240x240 RGB565). Review the mod-wheel Phase 1 implementation (branch lane/fmb-modwheel-ui, tree e5c7bf73, base 94197fc8) against the UX spec below. Then design a smaller version.

SPEC (sha 9031d6dc), summary:
1. Reuse the shipped draw_readout box: 224x50 at (8,103), with a part-colour frame. Stay on the current page, with no page jump. Draw only in ui_frame; smk_wheels only sets a flag, a snapshot and a timestamp. No note-scan, ISR or midi_in work. Do not use say(), because it wipes the header.
2. Text is all caps. FONT_S/B/XS fold i/e/o/h to capitals.
   - Single target: FONT_B "{ENGINE} {A|B}  {PARAM}" (e.g. JUNO A  CUTOFF, CHICAGO A  CUTOFF, MIAMI A  WOBBLE, DRONE A  BRIGHTNESS), with the live value in FONT_M and the "%" in FONT_S.
   - Two CC1 targets: two FONT_S lines that name both engines and both params.
   - No target (909/808/BREAK/FX/master): "UNASSIGNED" with no number, once per gesture.
   - Never show "CC1". Never call Miami a 303. Take the engine from the latched part.
3. Timeout is 900 ms after the last wheel event and is refreshed while the wheel moves. The knob and the wheel share the box, and the latest event wins.
4. Value is a percent: (live*100+63)/127.
5. At rest the live value is 0. Optional: a dim "PATCH nn %" line (already dropped for flash).

Owner requirement: show the real parameter name and value, both targets when there are two, and an honest "unassigned". Never show CC1, and never interrupt notes.

Problem: this adds +876 B of flash, and the Elite is 628 B under the floor. We need a design about 630 B smaller, for example by sharing more with draw_readout or reusing name strings that are already in flash.
