### Q1 area: sequencer / engine / project (seq/, app/engine.c, app/project.c)

Q1.1 **bug** firmware/src/seq/sequencer.c:1086-1093 (writer) and :399-401 (audio-ISR reader).
`seq_chain()` runs in the main loop and writes `chain_a`, then `chain_b`, as two separate byte stores.
At a bar boundary the audio ISR reads `chain_a`/`chain_b` four times. If the ISR runs between the two
stores it sees a mixed pair. Example: cancel chain 3..6 -> (0,0): the ISR can see (0,6) and plays a
0..6 chain for one bar (wrong pattern), or sets a chain the user never selected.
Callers: ui.c:2198, 2255, 3382, 3389, 4204.
Fix: store the pair as one `volatile uint16_t chain` (a | b << 8) written with one store, or write both
inside `irq_save()`. In the ISR, read it ONCE into locals before comparing. No behaviour change except
removing the torn state.
Test: new tests/host/seq_chain_atomic_test.c. Add a test hook (or the real `s->chain` after the fix).
Simulate the ISR running between the two stores (call the bar-boundary path from a store hook). Assert
that the next pattern is always from the old chain or from the new chain, never from a mix. Register
the test in the host suite.
