How symbols were matched
------------------------
Exact name for stable source symbols. LLVM locals (.Lswitch.table.N,
describe_pages.refs.N, process.N, .L.str.N, .L_MergedGlobals.N) are
renumbered by LTO when ui.c grows; matching them by the numeric suffix
is a false "grew/new/gone". They were rematched as a multiset of
(stem, size, type):

  describe_pages.refs  — 24 symbols, 416 B both sides, identical size bag.
  .Lswitch.table*      — 16 symbols, 496 B both sides, identical size bag.
  .L.str.*             — 4 symbols, sizes 1, 7, 12, 14 both sides (renumbered).
  process / note / decimate / inputs / … — same sizes, new suffix only.
  .L_MergedGlobals     — BSS reshuffle; section .bss +276 is the truth
                         (chord_lab_cache 268 + seq_chord_second 4 + 4 pad).
                         Individual MergedGlobals "growth" is not real flash
                         and is not real RAM growth either.

Those groups net to 0 and are omitted from the table below.

Where the 44 B residual goes
----------------------------
New C literals that are not inside a sized rodata object (the pointer
tables only count the pointers). Followed from chord_qual_suf and the
folds/short helpers:

  "min" 4, "min7" 5, "maj7" is a second copy (ck already has one at
  0x0206f790; T1 also has 0x0206a425 — not merged), "5" and "7" are
  shared with existing literals, "minM7" 6, "abdkmnprstxz" 13.
  Plus a few bytes of .text alignment (gaps 9,732 → 9,776).
  Together they account for the +44.

  "maj7" is the only real duplicated new-ish literal (5 B extra).
  "  ", "STEP ", "WRITE ", " TIE", " ACC", " SLIDE" already existed.

Inlining flags
--------------
  chord_label_fmt, chord_note_short, chord_lanes_prefetch,
  onset_chord_of, chord_sounding_clamped, chord_sound_midi,
  chord_name_lower, chord_lanes_prefetch have NO symbol: they are
  inlined. chord_label_fmt is inlined into chord_label_cached
  (1,308 B) — that is the main "inlining" cost. It is a SINGLE call
  site, so this is one large body, not a duplicated copy.

  draw_303 (+384) and draw_knobs (+230) do NOT inline the namer.
  T1 x0x.dis: both CALL chord_label_cached. draw_303 also calls
  chord_from_lanes, put_note, night_mark, lock_marks, note_start_of.
  The +384 is the required multi-pitch roll (lo/hi over every onset
  pitch, night_mark per pitch, TIE at each y, slide root-to-root,
  p-lock on root only, prefetch, held-line prefix/flags + cached
  call). The +230 is the NOTE-cell call (seq_bass_poly,
  engine_bass_bank, chord_label_cached, lab.cell / lab.cell_font)
  plus stack/prologue for a ~200 B chord_label_t on the draw_knobs
  stack of an already 5 KB UI_DRAW function. Not an inlined-helper
  blow-up of fmt into the draws.

  held_chord_get is NOW a standalone 100 B (was inlined in 94197fc8).
  held_note_by calls it and shrank 492 → 430 (−62). held_note_of is
  gone (−24); onset_chord_of (inlined into cached) calls
  note_start_of + held_chord_get. Net around this path is small.

  Helpers that DO have their own symbol (put_note, chord_try_cell,
  chord_name_paint, chord_name_caps, chord_name_folds,
  chord_has_slash, chord_label_fallback, chord_from_lanes,
  seq_chord_symbol) are CALLED from the inlined fmt, not inlined
  again. Sharing put_note is already done.

Cache struct (268 B BSS)
------------------------
  Key:  uint8_t valid, part, pat, step, onset, kind, nstore;  /* 7 */
        int16_t trans; uint8_t store[6];                      /* 8, packed */
        char prefix[20], flags[32];                           /* 52 */
  lab:  cell[32], symbol[16], fallback[12], notes[48], held[80]; /* 188 */
        2 font pointers + recognized/nsound/nstore + pad;        /* ~12 */
  Total 268. Draw paints only cell/held/fonts. prefix and flags are
  in the key, so draw_303 ("STEP n  …", " TIE ACC SLIDE V###") and
  draw_knobs (prefix=0, flags=0) MISS each other every frame and
  run fmt twice. Pool is not used.
