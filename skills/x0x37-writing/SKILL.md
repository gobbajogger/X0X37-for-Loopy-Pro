# Write clearly

### Rule 15: strict STE

Use strict ASD-STE100 for all output and saved text. This replaces the public skill's 80% default.
Use complete sentences, one idea per sentence, and direct verbs. Put conditions before actions.
Preserve facts, uncertainty, negation, exceptions, technical terms, and literal commands. Do not remove a condition to shorten text.

Required sources: [asd-ste100](../asd-ste100/SKILL.md), [strict notes](../asd-ste100/references/strict.md), and [official rules and dictionary](references/strict.md).
Before each output, check the text against those rules and the dictionary.
Do not claim compliance without those checks. For another language, use the same clarity rules without an STE compliance claim.

Use "behavior" and "colour" in prose; keep code spelling.
Before using project terms, read [their definitions](references/terms.md).
Use [caveman](../caveman/SKILL.md) only for an explicit or matching compression request. Grammar, facts, conditions, and technical content take priority.
Optional companion skills are not required.

For skill installation, source checks, or repair, use [source status](../../docs/SKILLS.md).
If a selected source is missing, report it, continue independent work, and restore it from its pinned source when needed.
