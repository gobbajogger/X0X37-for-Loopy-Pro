# Writing style and terminology

### Rule 15: strict STE

Use strict ASD-STE100 in every output, including saved text. Obey [rule 6A](../x0x37-task/SKILL.md).
Write one idea in each sentence. Use complete sentences and direct verbs.

Keep each instruction short. Put its condition before its action.
Keep facts, uncertainty, negation, exceptions, technical terms, and literal commands.

Do not remove a condition to shorten the text.

Use the installed STE skill in strict mode. This project instruction replaces its 80% default.
Read [asd-ste100](../asd-ste100/SKILL.md) and its [strict notes](../asd-ste100/references/strict.md).
Use the official rules and dictionary through [strict references](references/strict.md).
Read them one time per task. If these instructions change, read the changed sections again.

Before each output, use the rules and dictionary to examine the text.
Do not give a compliance statement without the applicable rule and dictionary checks.
For another requested language, use the same clarity rules. Do not give an ASD-STE100 compliance statement for that text.

Use "behavior" and "colour" in prose. Keep code spelling.
Use these terms with the meanings that follow:

- "Owner": the project owner.
- "Task agent": the agent responsible for the task.
- "Orchestrator": an assigned coordinator.
- "Loop slots": flash slots 1–3.
- "Gate": a complete formal script run.
- "Bluetooth": Bluetooth Low Energy MIDI. Preserve exact `BLE` identifiers.
- "Pairing": security with saved bonds.

Initialize [caveman](../caveman/SKILL.md) for explicit Caveman mode or a matching compression request.
Keep grammar, facts, conditions, negation, and technical content. These take priority over compression.
Verify installed sources in [skill status](../../docs/SKILLS.md) when you use or repair them.
Never claim an unread skill was used. Optional companion skills are not required.
If a selected source is missing, report it and continue independent work. Restore it from its pinned source when needed.
