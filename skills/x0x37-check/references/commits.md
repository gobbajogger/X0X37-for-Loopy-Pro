# Commits and lane handoffs

Apply the current [delivery workflow](../../x0x37-workflow/SKILL.md),
[continuation contract](../../x0x37-workflow/references/handoff.md) and
[owner decisions](../../x0x37-owner-decisions/SKILL.md).

Use **only** connected GitHub access for `gobbajogger/X0X37-for-Loopy-Pro` and its **default commit author/committer**. Do not set or require a custom Git `user.name`, `user.email`, environment author, `--author`, or connector author override, including historical `genkigenki` instructions. Original source copyright notices and test-only fixture identities remain unchanged; neither configures a project commit. Do not rewrite existing commits to change attribution. Group related repairs into coherent commits with relevant validation.

Check the base, existing edits and current owner. Use an isolated branch in the
assigned lane; branch names describe the current owner and topic, not a fixed
historical roster. Never rebase another agent's work. Fetch or rebase only when
needed against the approved source.

The assigned integrator owns firmware branch order and shared integration refs.
Deliver authorized source to the approved destination through an isolated branch;
verify its remote head, parent/tree and changed bytes before reporting delivery.
A local-only limit applies when it is part of the current authorized scope. A
checked local commit or handoff alone does not complete a request that requires
remote delivery, integration or another result. Continue the next authorized
action through the existing accountable owner.

On a transport failure, check the actual Git/API capabilities and whether the
operation already succeeded before retrying through a supported authorized route.
An actual permission, approval or policy denial remains binding; do not route
around it, force push, change protections or overwrite another active writer.
Record the exact dependent blocker and continue independent authorized work.

Include the immutable commit/input references, changed files, applicable checks,
limits, next action, one receiving owner and usable result reader in each handoff.
Verify the receiver's first scoped action or matching result as required by the
continuation contract; a sent report is not proof of execution.
