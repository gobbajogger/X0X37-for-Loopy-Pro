# Start a task

First apply [chat routing](references/routing.md). Preserve the current project context and delegated owner.
Use a qualified execution route for the bounded work that needs its tools; an active capable owner needs no additional launcher.

Search relevant product decisions and behavior. Do not load the full decision history by default.
Old plans, rosters, logs, and archives are evidence. They do not assign work or grant approval.

### Rule 1: protect data and sources

- Keep work in approved isolated repositories. The public project repositories and nonsecret technical evidence are not private merely because development is owner-tested.
- Deliver externally only within the owner-authorized destination and action scope; reuse applicable standing permission. Temporary private storage is not a permanent publication ban.
- Never push, merge, or package `refs-oscuro`.
- Keep proprietary JieLi SDK and toolchain files out of commits and bundles.
- Preserve licensing, model guards, flash and RAM limits, features, and sample quality.

### Rule 2: process and edit ownership

Use an isolated lane per task and finish it with its accountable owner. A fresh receiver is needed only for a real transfer under the [continuation contract](../x0x37-workflow/references/handoff.md); do not create another copy.
At task start, check other project chats. Read their current scopes before shared work; refresh stale information.
Before thread contact, shared changes, or process cleanup, read [ownership](references/ownership.md).
It defines context requests, completion notices, task handoffs, process ownership, and permitted contact.

### Rule 6A: finish authorized work

Load only the current step's instructions. Read each selected skill or reference one time per task.
A link alone is not a trigger. Do not preload later steps.
Same-task follow-ups use loaded instructions. After a source change, read its changed sections.
Claim skill use only after reading it. Current owner instructions take priority over old checkout text and saved handoffs.

Complete authorized work and required checks. Carry permission forward under [rule 14](../x0x37-owner-decisions/SKILL.md); do not ask again.
Use current, model- and action-specific device permission under [rule 14](../x0x37-owner-decisions/SKILL.md). Elite recovery and flash remain withdrawn; read-only Pro investigation belongs to the assigned integrator. Retired roles do not block independent authorized work.
Default to development under [rule 11](../x0x37-integrate/SKILL.md). For code review and PR delivery, select the explicit mode in [x0x37-workflow](../x0x37-workflow/SKILL.md); installed skills alone do not select a mode.
State the real blocker and next action.
Report verified results only. Separate source review, host tests, target builds, gates, installs, and device tests.
Include relevant unchecked inputs and checks that did not run. A PASS does not expand permission.
Before all output or saved text, initialize [plain writing](../../.agents/skills/x0x37-writing/SKILL.md).
Give the result first. Keep facts, conditions, uncertainty, and evidence.
