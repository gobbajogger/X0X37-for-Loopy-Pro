# Evidence, continuation and receiver consumption

Apply the [current workflow](../../../../docs/rules/workflow.md). Keep the original
request/outcome, existing owner, exact inputs, owned paths, current permission,
checks and requested completion criterion. Git and the approved coordination flow
carry durable evidence; a chat claim is not remote delivery.

Every actual delivery records full source head/tree and branch, applicable command
exits, failed/unrun checks, produced artifact identities, remote/readback receipts,
the receiving owner and one next action. For builds include model/config,
toolchain/SDK pins, package/controller size, SHA-256/CRC and budgets. Do not expose
private inputs. Deduplicate by repository, request, candidate and evidence revision.

Report each meaningful result, then continue the authorized next action. A bounded
claim or report is not completion of an unfinished outcome. Root/owner replies and
routine ACKs are not prerequisite steps. Do not open empty PRs or repeat unchanged
audits when the requested queue is complete or only genuinely gated work remains.

Use the current capable executor unless a real transfer is needed. For a transfer,
record exact inputs and allowed scope, release the previous writer, verify one
supported receiver or qualified relay, and retain a supported result reader.
Reconcile uncertain creation before retrying. Consumption is the receiver's actual
first scoped action on the pinned inputs, not its title, queued prompt, active flag
or acknowledgment. Direct parent access is optional when a qualified relay reads
and verifies the real result. Do not invent IDs or bypass a denied route.

An unread or stale queue is unknown, not NO_CHANGE. A required missing/failed check
blocks its dependent action; keep independent ready work moving. A scheduler run
marked completed is not request DONE. Mark DONE only when the declared outcome,
applicable evidence and actual delivery agree. Source-only completion does not
require unrelated future hardware or publication proof. Distinguish source,
HOST CHECKED, BUILD_ONLY, DEV CHECKED, QA, merge, publication, served bytes and
hardware proof. Missing or negative proof is never PASS.

Before ending an execution with pending work, persist and read back the checkpoint,
next owner/action and supported continuation. If no route exists, retain a precise
BLOCKED/PENDING dependency and retry trigger; do not claim continuous future runtime.
