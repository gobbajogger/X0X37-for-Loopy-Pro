PLAY DnBOX

Hands on the sound.

Notes are genuine 37-key hardware events, from C3 to C6. The triad sends C4, E♭4 and G4 into the currently selected firmware mode. It only makes sound if that mode accepts keyboard notes.

Pads, faders, wheels and knobs

Computer keyboard: A–' plays C4–F5; Z / X shifts octave, Space is SEQ PLAY, R is REC, 1–8 play the upper pads, arrows and comma/period turn the first three knobs. Focus a piano key with Tab and press Space or Enter to hold it.

    GOOD TO KNOW

    What this demo can and cannot prove

    Actual runtime

    JieLi CPU and peripherals are emulated with the upstream MIT-licensed fm1-emu Rust/WASM engine; sound comes from the firmware's own I2S buffers through an AudioWorklet at 44.1 kHz. Not a rendered video or a JavaScript substitute synth.

    Sound is a performance test

    Start audio with a click. Watch the live speed, load and dropout warnings. Desktop Chromium is the initial target; Firefox, Safari and mobile performance have not been qualified. A fast emulator is not proof of hardware timing.

    Low queue, honest latency

    The default audio queue allowance is 512 frames (about 11.6 ms at 44.1 kHz), not 2.5 seconds. This is not measured key-to-speaker latency. You can try ?ahead=256 or ?ahead=1024; smaller queues may crackle on slower computers.

    Safe boundaries

    There is no WebUSB, WebSerial, flashing or device write here. Local flash saves and export live only in this browser. Model/version metadata and packages must match before boot; no unfinished 0.0.26 build is advertised as ready.
