# Actual firmware teaching in HTML

The local lesson lets a musician place four kicks, hear the real emulated transport, read an actual save reply and keep a browser backup. Its HTML screen has firmware-derived header, drum-row, step-cell and parameter regions. Every displayed colour and glyph pixel comes from the running published 0.0.25.1 firmware; no separate browser state machine, substitute font or invented parameter value is used.

This is reviewed development source for a private local integration, not a standalone public trial or a deployment. Apply the `site/` overlay to the already assembled private host pinned in `SOURCE-PINS.json`. Mount the original, unmodified runtime at `/firmware-runtime/` and keep its WASM, worklet, package parser, persistence, controls and catalog together. The local entry is `/firmware-lesson/`; website Emulator and Guide routes discover it. The previous local workspace assembly remains a separate accepted input, not replaced by this overlay.

## Exact authority and coverage

`SOURCE-PINS.json` identifies the firmware, actual UI/GFX/pictogram source, original emulator and package/WASM bytes. The original runtime source is [the pinned emulator branch](https://github.com/gobbajogger/X0X37-for-Loopy-Pro/tree/431d0db82cbadca761fb32c6548ca4765875324f); the UI authority is [published0.0.25.1 source](https://github.com/gobbajogger/X0X37-for-Loopy-Pro/blob/79280e763341d03ba43266d3e25dad66f12de860/firmware/src/app/ui.c).

Only 909 SEQ / BD / Pattern 1 / page 1 / REC off has semantic grid labels and safe step-placement checks. Actual captures of all eleven drum-row selections allow a guarded return to BD. Positively matched `SAVED` and `SAVES WHEN STOPPED` headers have accessible text. Other messages remain unconfirmed; other layouts retain exact live HTML pixels without claiming full semantic reconstruction. Native display pixels are never rewritten. The original interactive SMK-37 panel shares the same machine and remains available.

The website sends only the existing `dnbox:input` event schema. Paired input ownership, unique timed activation tokens, keyboard-only per-button blur, global cancellation, deliberate-route heading focus and history position/focus restoration keep the actual session coherent. Browser-persistence status and backup actions are the original runtime's actions; firmware Save and a readable browser backup are separate results. The iframe denies MIDI and USB access.

## Private inputs and qualification

Captured recognition templates, raw images/RGBA/audio/video, browser backups, firmware packages, WASM and original component payloads are intentionally outside this source-only Git delivery. `prepare-references.py` documents the exact conversion and observed source inputs for the private `references.json`. It is recognition data only, never generated display output. The current runnable private candidate retains that file and the original runtime mount. Do not describe this code-only projection as a self-contained hosted website.

The Python qualification scripts target the existing lawful producer environment and byte-verified local fixture. They record offline package replay separately from network delivery. `check-retry.py` provides one real loopback HTTP 503 for the original worklet, then tests the primary retry without changing runtime bytes, permissions or browser flags. Existing source, pixel and musical proof is reused where unchanged. The final acceptance receipt identifies actual checks and remaining limits.

Hard realtime audio, acoustic latency/listening, other browser engines, physical mobile performance and hardware operations are not qualified by these HTML checks. This work changes neither firmware nor the emulator. Shared refs, merges and publication remain with their existing owners and gates; all actual refusals remain binding.
