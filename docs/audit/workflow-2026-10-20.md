  configuration, toolchain, SDK, reference pins and contents, host executables,
  Python dependencies, optional Emscripten coverage, and actual external runner.
  Capture occurs before reuse and again before a result. Old/missing identity
  cannot qualify. Per-run logs preserve earlier provenance. Generated Emscripten
  caches and Python bytecode are outputs, not identity inputs. Content hashing
  avoids an mtime cache that could miss replaced bytes.
- Development records use schema 2, bind configuration/plan to provenance, and
  reject dependency drift during validation. Install consumers still check the
  exact source, configuration, artifacts, logs, budgets and queue. They verify
  transferred provenance without requiring the build SDK on the installer.
  `sync_results_to_mac.sh` transfers the new sidecar. `install_gate.sh` ships the
  helper and the gate fingerprints its actual installed executable name.
- The decision parser previously skipped the dated-heading/prose forms used by
  Build target scope and On-demand rules. Both now use dated bullets. All current
  sections are checked; unknown prose/list shapes and sections without entries
  fail visibly. Historical text and exact owner quotes remain unchanged.
  Shared words are a pointer sanity check, not proof of semantic compliance.
