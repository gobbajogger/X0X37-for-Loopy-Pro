## GPI-001 — HIGH — explicit model flag bypasses package model validation

**Source-confirmed:** [`tools/make_pages.py:80-98`](https://github.com/gobbajogger/X0X37-for-Loopy-Pro/blob/c9718ae833eb64a5191c350922593df8a36017c9/tools/make_pages.py#L80-L98) parses the actual package product and verifies it is a recognized release identity, then uses `key = key or model_key(product)`. But [`main_multi():280-287`](https://github.com/gobbajogger/X0X37-for-Loopy-Pro/blob/c9718ae833eb64a5191c350922593df8a36017c9/tools/make_pages.py#L280-L287) passes the requested `--pro / --elite / --mke / --fm1` key **into** `pkg_entry` and compares its returned key back against that same supplied key. That test cannot detect when `--elite` points at a Pro package (or `--fm1` points at an SMK package).

**Reproduction:** on Linux x86-64, an isolated Python 3 probe copied the exact `installer_model`, `model_key` and `pkg_entry` bodies from the live generator blob and imported the unchanged production `web/make_site.py` (`593bf56b4dde7f3a5138fe522210ec85d1159b46`, matching current main). A synthetic `SMK-37 Pro_9002000` package containing the required loader marker was passed as `pkg_entry(pro_fwsc, "audit", "elite")`. **Observed:** returns `key=elite`, filename `x0x37-audit-elite.fwsc`, and embedded identity `SMK-37 Pro_9002000`; the existing `if k != key` comparison would accept it. Exit 0; probe SHA-256 `cb01bb49cc54e02205be39f74e22ce375363357ff5d460d264f4248e827366fe`. A proposed independent `model_key(product) != requested_key` check rejects this mismatch and accepts correctly tagged Pro input in the same probe.

**Impact:** the generated version/model catalog can represent one model's firmware as another. The browser may have additional runtime guards; this audit **does not claim a wrong-device flash has happened** or that a complete installer was run. This is a model/identity publication-gate defect that must be closed before generating new packages.

**Correction/acceptance:** calculate the actual model key from the *embedded product* in `pkg_entry`; reject any explicit mismatching key before forming filename or metadata. Add negative tests for all mismatched Pro/Elite/MKE/FM-1 flag/product pairs and positive tests for each matching pair, then build a preview and verify that published catalog key, embedded product, filename and actual package bytes all agree. Coordinate the focused generator repair with PR #20's owner, not on the same active lane.

## GPI-002 — MEDIUM/HIGH — republishing a version with one model silently discards its other model

**Source-confirmed:** [`merge_version():174-192`](https://github.com/gobbajogger/X0X37-for-Loopy-Pro/blob/c9718ae833eb64a5191c350922593df8a36017c9/tools/make_pages.py#L174-L192) removes the existing record for the same version and creates a new models dictionary using only the freshly passed models. [`write_site():202-212`](https://github.com/gobbajogger/X0X37-for-Loopy-Pro/blob/c9718ae833eb64a5191c350922593df8a36017c9/tools/make_pages.py#L202-L212) derives its firmware retention set only from the new catalog. The generated site can therefore silently omit both the previous model selection and its archived `.fwsc` when only one model is republished under an existing version label. PR #20 adds a missing-file check, but **cannot detect** the removed model because its path is no longer in the catalog.

**Reproduction:** isolated Python 3 state-model copies exact current-main `merge_version` behavior and `keep` expression. Starting version `0.2` with Pro and Elite, then merging a Pro-only `0.2` entry, yields model set `{"pro"}` and retention set `{"x0x37-0.2.fwsc"}`: the formerly published Elite package is not retained. Exit 0; probe SHA-256 `d98aa1a8b0c52fb8e99a2956d7f1a5299624de56c66125bfe86a8f33315b4b54`. The complete current-main generator/site write was **not executed** in this sandbox.

**Correction/acceptance:** explicitly preserve existing model metadata/firmware files for same-version partial updates (or fail closed requiring intentional full model replacement), with tests for same-version Pro-only and Elite-only rebuilds, renamed/aliased versions and missing archive bytes. Validate that every catalog entry points at a present hash-matching firmware object and earlier published entries remain unchanged.

## UX reference review (ideas, not copied code)

- [WLED Web Installer](https://install.wled.me/) and its [open source implementation](https://github.com/wled/WLED-WebInstaller) make an unsupported browser visible immediately, distinguish basic from advanced configuration, provide manual firmware links when downloads fail, and show installation/build provenance. **X0X fit:** explicit Web MIDI capability/secure-context preflight and a non-flashing fallback; avoid an ESP-specific assumption that the selected device is automatically safe.
- [ESP Web Tools](https://github.com/esphome/esp-web-tools) documents HTTPS, CORS requirements, detected hardware/manifest matching and optional logs. **X0X fit:** explain model-identity checks and actionable connection errors, and keep a human-readable technical log; no adoption of ESP flashing libraries for JieLi Web MIDI updates. ESP Web Tools' implementation is Apache-2.0 and WLED WebInstaller is MIT; these are pattern references only, with no imported source or assets.
- PR #24 already addresses visible model choice, guided steps and accessible status. **Do not duplicate** these improvements before exact-browser testing of that PR.
