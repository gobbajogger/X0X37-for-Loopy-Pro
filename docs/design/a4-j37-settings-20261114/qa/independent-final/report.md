Ranked actionable findings:

1. **Low — enlargement wording disagrees with displayed scale.** `#large` has a 720×720 backing store but displays at 480×480 CSS pixels, so its on-page size is 2× the 240px LCD. The aria label says “Three-times pixel enlargement,” and README calls the adjacent view 3×. The figcaption's “3× export” is accurate for the backing store, but the adjacent-view wording is misleading. Use “2× display / 3× export,” or display it at 720 CSS pixels where feasible. This does not affect native evidence.
2. **Low — NOTE LOCK loses the standard editable-row cue.** Its focused footer substitutes “Runtime flag; not saved” for “K3 −/+ edits; > increases.” The persistence distinction is useful, but a player who reaches this row has less local confirmation of how it changes than on every other editable row. Preserve both ideas through a bounded two-line treatment or concise combined copy, without changing the source interaction. This is a consistency refinement, not a broken edit path.
