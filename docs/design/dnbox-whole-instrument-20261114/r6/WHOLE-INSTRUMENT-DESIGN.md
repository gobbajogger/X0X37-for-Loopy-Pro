# DnBOX R6: connected workflow design continuation

R6 replaces R5's generic whole-journey disposition with concrete interaction work. It is a proposal under development, not a completed whole-instrument acceptance or firmware implementation. R5 `78f861af8dbda894152a355b1fb42a2efee7b3c7` remains immutable reviewed history: useful conservation study, incomplete whole design, partial fidelity. Its full report hash is `e0412c26d535fee223e05a18254c4bdfbe14866b59ca3be8dad6b60070b8ecc1`.

The design criterion is easier musical use. Existing useful native information, controls and fast routes stay. A new glyph is not a benefit by itself. New feedback uses source-owned state and existing regions; it must earn its recognition and readability tradeoffs in independent use.

## Concrete musical changes

**64-step correction.** Native OCTAVE paging, hidden stored content, held pitch exceptions, length/rate/direction, conditional chance and original release remain. The selected-instrument region occupies only formerly unmapped drum K7/K8 cells. It now keeps absolute range available when a pending cue takes the native header range; while a step is held it shows its nondefault chance. No new editable control is invented. Source captured STEP64:95% and P1→P2; phase is qualified separately. A held drum-page change does not retarget its old release. Cue adoption invalidates its old lock owner; a compact BASE/old-pad notice exposes the new scope without silently keeping an obsolete lock armed.

**Motion write, one-pass override, precise clear.** Existing per-parameter dots stay. A small selected-row gutter cue exposes remaining modeled override steps; outlined/filled marks separate a request from a captured matching step. A turn changes base first. REC+playing requests capture on the next matching part step; short gaps interpolate. RECoff override suppresses lane playback for a part pass while retaining the base edit. BT+assigned knob clears the whole lane; an eligible held step takes priority and clears only that position. Pool exhaustion may refuse a new lane after base changed. No new capture class, dedicated physical light or wall-clock audio phase is invented.

**Five-part copy.** The existing occupied confirmation retains IT HAS NOTES and full-size SCALE YES/PATCH NO cues. Five compact rows add actual current source→destination IDs, old/new content and source-owned lane counts. Source IDs freeze at target press, not BT-down, and exclude queued targets. Controls/confirmation counts stay. Each part preflights capacity, but the five-part result can be partial. Copy does not select/cue destination or copy global sound/FX. The source's immediate empty/motion-only-destination behavior is retained and remains a limitation; no extra confirmation is silently added.

**Cue/mute performance.** Native musical thumbnails, left current ticks, chain underline, occupancy/tie content and current mute dimming stay. Two unused right-edge pixels show a part-coloured pending arrow for every queued part, rather than relying only on the909 target. With queued mutes enabled, a dashed mark under the lane name shows the pending toggle without dimming it early. Fresh actual capture has queued mutes OFF and immediate808 mute; the ON-policy model fixture is separately labeled. Source pad hues/used/current/held/playhead priority and button phases stay. CHORD selects the shared accent layer; SEQ/drum MIX toggles it without changing voice hits, while fresh PART pads audition only. Central white-key and pad holds share the final bright layer even with LIGHTS OFF. BT distinguishes queued/failed/unsaved frame predicates and active Song PATCH keeps its separate blink outside Song/Home. STOP/WAIT pending LCD remains steady; running pulse and physical cue blink remain separate.

**Phrase, correction, replay, repeated entry.** Current stopped NOTE/TIE/REST authoring, V100, write cursor, direct held pitch/gate/accent/slide, octave correction and original releases are executable model stages. The existing page strip adds REWRITE1–LEN on stopped rearm: visited cells are replaced, not moved into a new take object. Three distinct nonzero current3c41 PCM replays and native stored-step views are retained separately. The observed upperG4/lowerG3 capture discrepancy is disclosed; matching proposed G4 fields follows source intent, not an established device fix. Running duration/poly capture, full37 recording, persistence and listening acceptance remain open. CP1→selectedCP2→CP3 is unchanged.

**Scoped panic and recovery.** FX+SEQ keeps its source two-press chord, release consumption and transport. A brief footer acknowledges NOTES OFF / TRANSPORT RUNS, then restores the useful hint. Both members must release before rearming; a fresh note is the next musical action. Actual source evidence includes nonzero held sound, a zero-RMS released interval and nonzero fresh note. No unconditional silence, tail kill or host reset is promised. SMC's same-peer DAW bank chord and Clip Keys NOTE REPEAT release remain different routes.

**Ordinary Song.** R5's internal authoring defect is repaired. Pad writes all five assignments and advances; K5 selects stored/END; both BAR pages edit the proper fields; repeats and low mute bits remain separate. Native BAR/pattern identity tiles and repeat pips are restored. At192bars there is no extra END. PLAY reads authored bars in the explicit model boundary path. This is retention/prototype repair, not a new firmware feature or future capture-strategy acceptance.
