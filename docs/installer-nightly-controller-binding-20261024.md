## Root cause and concrete baseline reproduction

The DEV installer allowed a manually selected, structurally valid `ctl.img` to be inserted into a catalog-approved `.fwsc` after only format/CRC/ABI validation (`ctlProblem`). It did not compare the actual controller bytes to the publisher-approved **per-model `controller_sha256`**. Independent approval of a firmware/controller byte pair would therefore have been bypassable by optional replacement controller bytes. **In a connected V8 synthetic source-exact reproduction, the original `$("go")` handler invoked `insertCtl()` and `run()` once each with a nonmatching controller SHA (1/1 expected unsafe reproduction, no actual MIDI/device).**

A separate existing registered regression contained an obsolete source-order regex: after `writing = true`, the current source correctly invalidates `scanSerial` before `ctlLoadSerial`; the obsolete check wrongly required `ctlLoadSerial++` to be immediately next. The original test failed during source assertion; with only that stale assertion bypassed, the original eight behavioral cases passed in connected V8. The new test verifies both invalidations without bypassing either.

## Repair in this sole-owned existing PR

1. Keep the optional `ctl.img` format check, then compute its SHA-256 via existing `sha256Hex`, recheck selection generation and writer state after digest, and store bytes + digest together.
2. Immediately before any DEV-controller insertion or updater run, require selected current approved model metadata and exact equality `ctlHash === model.controller_sha256`. Mismatches stop before `insertCtl` and writing.
3. Provide an accessible EN/JA-localized **Remove controller** action allowing owner to continue the existing Bluetooth-less installation path. Clearing invalidates pending file reads and clears digest. Prevent clearing during writer lock, restore after writer completes/denies permission.
4. Correct the registered source-order assertion and extend the test file with positive/negative digest/model/catalog/async-clear scenarios. The separate local arbitrary `.fwsc` import, recovery, backup, publisher allowlist, Release-import prohibition and stock safeguards remain intact. No binary `.fwsc`, controller, proprietary SDK, DSP, or samples are included.
