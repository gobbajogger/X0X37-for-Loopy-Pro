# NIGHTLY browser installer — direct-download eligibility and GitHub Releases safety

**Role:** Firmware repository browser installer source UX/safety owner. **Status:** SOURCE-COMPLETE CANDIDATE, independent QA/source integration and website mirror pending. No firmware release, hardware flash, hosted HTTP approval or production promotion.

## Owner-visible behavior

**Before:** A GitHub Release containing a matching `.fwsc` filename silently became a selectable installer catalog version even when there was no package checksum, source/build QA or approved model/controller/backup evidence. The direct **Download this package** link appeared independently of the automatic-install guard. Users could obtain a package that had never passed NIGHTLY checks.

**After, on this proposed source branch only:** The installer no longer auto-imports arbitrary GitHub Releases. The version/model list and direct download link share an explicit **independently checked, exact-version/model/SHA/source/licensing/host approval** predicate. An absent or revoked approval hides the package and clears a stale link; a truly approved DEV package can be shown without prior owner-operated device PASS (standing NIGHTLY test policy). The source-compiled publisher-approved tuples are intentionally **empty** until independently verified real build/hosting evidence exists. Local arbitrary `.fwsc` selection, stock/recovery links and sample-backup/write confirmations remain separate; firmware and controller code was not changed.
