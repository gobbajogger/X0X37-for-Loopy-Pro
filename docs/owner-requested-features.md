## Known quirks and required handling

### Q01 — Physical Pause glyph historically functioned as STOP.
Use captured Pause Note 0x5D as context lock; PLAY handles play/pause; never guess another button code.
Evidence: SMC-13,14,17.

### Q02 — Repeated held Pause/PLAY/SELECT messages and missing releases can retrigger actions.
One deliberate separate hold unlocks; suppress held-repeat actions; cancel unsafe pending holds on lost release/disconnect.
Evidence: SMC-14,25.

### Q03 — DAW faders emit pitch bend per channel, knobs sign-magnitude relative CC, buttons Mackie notes.
Decode actual DAW messages, preserve zero/no-op and release semantics; do not treat ordinary musical pitch bend as arbitrary SMC input.
Evidence: source-proven protocol; owner asks reliable mapping/route isolation.

### Q04 — User preset/configurations differ: captures include CC40–47, absolute CC30–37; legacy MMC has no release.
Current explicit owner decision is ignore SMC User mode. Do not resurrect obsolete USER/MMC behavior or infer custom CC assignment.
Evidence: explicit retained owner User-mode exclusion request.

### Q05 — Two similar SMC peers can have identical names, separate handles and simultaneous held actions.
Retain two independent identities, target locks, pickup, queues and Solo/FX ownership; one disconnect must not release surviving peer.
Evidence: SMC-02,03,25.

### Q06 — Double pickup against old display state and target state; stale unmute level.
Single actual-target pickup crossing; unmute uses intended current physical fader behavior, not stale saved level or an extra pickup cycle.
Evidence: SMC-23.

### Q07 — Bank 2 of an eleven-sound kit has only three valid strips.
Tracks9–11 active; strips4–8 inactive/unlit and never fall through into navigation. Both drum MIX and SEQ target same kit/sound.
Evidence: SMC-21,31–33.

### Q08 — Keyboard navigation and unchanged feedback packets can spuriously open/restore overlay.
Quiet context updates; only meaningful SMC activity opens overlay; release starts timeout; no stale page restoration.
Evidence: SMC-08,09.

### Q09 — Locked target is distinct from currently visible keyboard page.
Do not block usable buttons; resolve FX/context against intended captured target without redirecting held actions; navigation stays available.
Evidence: SMC-13,15,18.

### Q10 — Queued pattern changes formerly overwrite rather than accumulate.
Repeated next/previous presses accumulate pending cue; opposite press cancels appropriately.
Evidence: SMC-24.

### Q11 — Cold Bluetooth OFF→ON and setting persistence originally required reboot/project save.
Live toggle; independent automatic device setting save. Safe-idle deferred storage is not immediate durable active-audio persistence.
Evidence: SMC-04,05.

### Q12 — Outgoing LED feedback and CONNECTED status do not prove incoming control delivery.
Preserve truthful state and actual-action tests; do not infer a transmission cause from idle zero-notification diagnostics or claim hardware from host tests.
Evidence: retained investigation and SMC-01.

### Q13 — Semantic effect bus enum order differs from physical strip order.
Use part_at/captured identity; physical order in recovered UI is 909,808,BREAK,303B,303A then returns/master.
Evidence: source-proven reference; no speculative remap.

### Q14 — A button pressed outside FX can be released after entering FX.
Release only the gesture/peer that originally acquired FX; never create an FX action from a foreign release.
Evidence: SMC-18,20,25.
