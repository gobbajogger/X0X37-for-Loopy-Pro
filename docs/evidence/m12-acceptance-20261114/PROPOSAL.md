# Isolated M12 acceptance repair proposal

The current strict evidence checker can validate a reduced, internally consistent inventory without consuming an independently expected release scope. It is a useful structural checker, but its PASS is insufficient for selected-release acceptance. Retain it and its existing 42 checks. Do not merge historical #822 wholesale: its parser requires retired tables, its evidence/selection target 0.0.24.5, and current package/preview source has no hook.

Proposed bounded repair: add a separate release-acceptance adapter in the canonical firmware repository, reviewed independently before integration. The integration owner chooses its final pathname and branch. This document is a proposal, not adopted source or accepted release policy.

1. The existing integration owner supplies expected candidate commit/tree, canonical ROADMAP commit/blob and an independently accepted release-policy commit/blob. Resolve these before invocation; never read the expected pins from the report or evidence being checked. Reject unavailable Git objects, pin disagreement, stale report/tool/evidence inputs and duplicate IDs.
2. The policy references selected canonical request IDs and their explicit acceptance obligations. It is executable scope for one release/stage, not a second request tracker. Record release identity and stage (source presence, hardware-test candidate, qualified release) so a source-only PASS cannot be used as functional or release PASS. Generation never grants policy approval. Retain baseline features explicitly selected by the accountable owner; do not silently narrow an already agreed release.
3. Parse the current ROADMAP's identified request tables, not retired Done/Master tracker headings or free-text DONE prefixes. Bind row IDs to table identity; #119 community library differs from nightly PR #119. Detect missing/duplicate selected IDs. Keep historical DONE IDs/aliases only through explicit reviewed mappings; reject ambiguous mappings. A parser change must be covered by the current pinned document plus small table fixtures before adoption.
4. Derive the required evidence inventory from the independently selected policy and reject a reduced local REQUIRED_ROWS.txt. Use Git object reads or independently verified source-closure bytes for candidate paths, source proofs and test implementation. A path that merely exists, matching 40hex strings, a literal runner name or a caller-authored PASS is structural metadata, not proof that a test ran. Bind existing exact-input receipts to test/tool/config/dependency closure; preserve FAIL and NOT_RUN. Reuse unchanged valid evidence. Source presence and behavior acceptance remain separate results.
5. Report every selected obligation as PASS/FAIL/NOT_RUN with exact proof pointers. Show nonselected roadmap items with their existing dispositions separately. Do not make every unfinished item a release blocker: #119 is DEFERRED, 26.7 extra engines DECLINED, M5 undefined/QUEUED with an explicit never-reask instruction, and best-in-class wording is aspiration. Policy selection cannot override these owner decisions: reviving deferred/declined work needs newer applicable owner authority; do not define or re-ask M5. Exclusion from this release policy must not delete or falsely complete those requests. Unknown status text must not silently exclude an explicitly selected item.
6. After adapter review, the package and preview owners adopt the verified report at their own entry points. The sole publisher independently enforces fresh verification before its actual first external write and demonstrates zero writes on negative cases. Preserve existing model/controller, host/native, memory/performance, catalog and device gates. Local preview tests cannot prove uploader adoption. No publisher or shared source file is changed here.

Required regression coverage for that implementation: selected row removed from evidence only; selected row removed from both mutable inventory and evidence while accepted policy stays fixed; self-consistent wrong ROADMAP pins; source changed under the same claimed SHA; omitted/changed accepted policy; current-layout parser coverage; same-input valid report; stale/altered report; deferred/declined/aspirational/undefined rows preserve their owner disposition and remain nonblocking under current authority; source-presence PASS cannot satisfy behavior/native/device obligations. Historical v2's 24 tests supply reusable trust-boundary coverage, not current-layout adoption proof. Its source/live external proof remains reusable as a separate source-identity component.

Deliver this proposal and test_m12_boundaries.py to the parent/current integration owner for policy selection and a bounded adapter implementation. The supplied probes deliberately remain red against the current structural checker (three missing acceptance boundaries). They add no automatic release requirements or publisher authority. A green adapter implementation and adopted call sites are subsequent work, not claimed by this stage.
