## 3. Concrete speed/reliability changes inside current owner rules

1. **Make #734 the only active merge/fix queue.** FMB owns it; one independent QA reader reviews source-matched proof. Freeze new features *into* #734 until a full green pass is posted. Park #735/#736/#737 as distinct unmerged drafts, compare their unique blobs against #734, and assign only missing deltas to the current owner. Do not open a replacement feature lane merely because a PR is stale. Merge the fully checked #734 into **wip/one-build only**, one green PR at a time. Never main/nightly.
2. **Use one pre-packed source manifest per exact candidate SHA.** Read GitHub tree+blob API; record paths, mode, size, blob SHA and tree SHA once. Reuse the verified complete snapshot and fetch only differences for later changes. Do not use zipball or network git. Refuse test evidence whose tested tree differs from current #734 head.
3. **Select the complete Library SDK V1.2.1 and approved Linux toolchain before tests.** Verify archive identity and required files without transmitting SDK binaries into GitHub. The V1.2.0 mounted archive and 11-file kit in #737 are not substitutes for the complete SDK. Preserve all permitted *_private.h and the factory assets required for host/firmware builds. No firmware builds were needed or performed for this documentation audit.
4. **Run the complete host suite in the assigned fresh classic thread, asynchronously inside that thread's runner with logged polling, then Elite and Pro.** Use the actual branch commands from tests/run_tests.sh and BUILDING.md; report test count and first failing names, exact SHA, elapsed time, exit code, firmware link output, memory/flash guards, artifact identity and a link to logs. Do not call partial/source-only/11-file checks a full PASS; do not import an earlier head's success.
5. **Enforce commit identity before new writes.** The only compliant Git author for this audit is gobbajogger with the numeric noreply email above. Add a pre-write capability check and post-write Git author inspection. If the active connector cannot set author, record that precise capability gap and use an authorized author-capable API route rather than silently creating more noncompliant history. Preserve branch ancestry without force push; reauthor only through explicitly authorized, safe isolated-lane work.
6. **Use short, targeted steers, not duplicate chats.** Before each order, apply the owner's supplied preflight. Send corrections to the live classic thread first; fallback to one plain PR comment if the chat will not load. Record current owner, single stage, exact SHA and next action. A fresh classic thread starts each new stage. Bots coordinate/relay only, and avoid browser tab indexing and unnecessary reloads.
7. **For UI changes, carry an honest before/after mockup and actual render evidence.** Include source-pinned proposed screenshots or mockups on the PR; label them proposals until validated. Do not reject permitted PNG/SVG mockups as “forbidden firmware binaries.” This audit changes no UI and needs no mockup.
8. **Keep all execution out of Actions/.github.** GitHub is the source and evidence ledger, not the firmware build runner. For possible REST throttles, record the HTTP status, timestamp and actual rate headers; on confirmed 403/429 follow documented backoff/Retry-After instead of retry storms. Do not assume a rate-limit failure from a loading failure. Respect platform-required confirmation prompts rather than claiming them auto-approved.
